## 1. 迷宫生成算法：迭代 DFS（递归回溯法）

### 1.1 算法选择与设计思路

本项目的迷宫生成采用**迭代深度优先搜索（Iterative DFS，又称递归回溯法）**，其核心思想是：从起点开始，随机选择一条未探索的路径向前"挖"，直到走到死胡同，再回溯到上一个分叉点换条路继续挖。

选择这一算法的主要原因：

| 需求 | 为什么迭代 DFS 合适 |
|------|------------------|
| 迷宫连通性 | DFS 保证从起点出发能到达**任意**通路单元格（天然连通图） |
| 单一路径导向 | 生成的迷宫解路径唯一（无环路），玩家体验更纯粹 |
| 可控复杂度 | 通过调整网格行列数即可控制迷宫规模 |
| 实时生成 | 30×30 的迷宫生成在毫秒级完成，不影响游戏启动速度 |

**为什么不用其他算法？**

| 算法 | 与本项目需求的匹配度 |
|------|-------------------|
| Prim 算法 | 生成树形迷宫同样保证连通，但偏向于生成短而多的分支，缺乏 DFS 的"长走廊"效果，迷宫趣味性稍差 |
| Kruskal 算法 | 生成随机性更强，但实现复杂度和内存开销更高，不适合前端直接计算 |
| 手动设计 | 迷宫不可重复，无重玩价值 |

### 1.2 核心原理：隔墙法 + 步进二

这是一个关键的设计细节。标准的 DFS 走迷宫是"从一个格子移动到相邻格子"，但在**迷宫生成**时，我们是"从一个通路格子，隔着一堵墙，打通到另一个通路格子"。

```
初始状态（全部是墙）：
┌───┬───┬───┐
│ █ │ █ │ █ │
├───┼───┼───┤
│ █ │ █ │ █ │
├───┼───┼───┤
│ █ │ █ │ █ │
└───┴───┴───┘

DFS 第一次开挖（从 (1,1) 开始）：
  当前格子: (1,1) → [PATH]
  随机选择方向: 向下 → 隔墙 (2,1) 打通 → 下一格 (3,1)
  ↓
┌───┬───┬───┐
│ █ │ █ │ █ │
├───┼───┼───┤
│ █ │   │ █ │  ← (1,1) 变为通路
├───┼───┼───┤
│ █ │   │ █ │  ← (1,1)→(3,1) 之间的墙 (2,1) 打通
└───┴───┴───┘
            ↑ (3,1) 变为通路
```

**步进为 2 的原因**：迷宫的通路和墙有各自的位置——所有**奇数行列**的格子是潜在的通路位置，**偶数行列**的格子是墙的位置。步进 2 确保每次移动都是从奇数格子到奇数格子，中间必然隔着一个偶数墙格。打通这个墙格，就连通了两条路。

### 1.3 算法流程

```
输入：rows, cols（必须为偶数，以保证奇数格子是通路）

① 初始化网格：所有格子设为 WALL（墙）

② 从 (1, 1) 出发，设为 PATH（通路），入栈

③ 循环（栈不为空时）：
   a. 查看栈顶元素（当前格子）
   b. 找到所有距离为 2、且在网格范围内的未访问邻居
   c. 如果有未访问的邻居：
      - 随机选一个
      - 打通当前格子与邻居之间的"墙壁"
      - 将邻居设为 PATH，入栈
   d. 如果没有未访问的邻居（死胡同）：
      - 出栈（回溯）

④ 通路生成完毕，将 (1,1) 设为入口，将最后一个奇数格子设为出口
```

### 1.4 代码解析

来自 `maze.js` 的关键代码：

```javascript
// 初始化全墙网格
_initGrid() {
    this.grid = [];
    for (let r = 0; r < this.rows; r++) {
        this.grid[r] = new Array(this.cols).fill(CELL_MAP.WALL);  // 1
    }
}
```

**逐步开挖**：

```javascript
_carve(startR, startC) {
    const stack = [{ row: startR, col: startC }];
    this.grid[startR][startC] = CELL_MAP.PATH;  // 起点设为通路

    // 四方向，步进为 2
    const dirs = [
        { dr: -2, dc:  0 },  // 上
        { dr:  2, dc:  0 },  // 下
        { dr:  0, dc: -2 },  // 左
        { dr:  0, dc:  2 },  // 右
    ];

    while (stack.length > 0) {
        const current = stack[stack.length - 1];

        // 找所有未访问的邻居（距离为 2 的格子）
        const neighbors = [];
        for (const { dr, dc } of dirs) {
            const nr = current.row + dr;
            const nc = current.col + dc;
            if (nr > 0 && nr < this.rows - 1 && nc > 0 && nc < this.cols - 1 &&
                this.grid[nr][nc] === CELL_MAP.WALL) {
                neighbors.push({ row: nr, col: nc, dr, dc });
            }
        }

        if (neighbors.length === 0) {
            stack.pop();  // 死胡同，回溯
        } else {
            // 随机选一个邻居
            const next = neighbors[Math.floor(Math.random() * neighbors.length)];
            // 打通中间的墙：dr/2, dc/2 就是墙的位置
            const wallR = current.row + next.dr / 2;
            const wallC = current.col + next.dc / 2;
            this.grid[wallR][wallC] = CELL_MAP.PATH;
            this.grid[next.row][next.col] = CELL_MAP.PATH;
            stack.push({ row: next.row, col: next.col });
        }
    }
}
```

**放置出入口**：

```javascript
_placeStartEnd() {
    // 入口固定在 (1,1)
    this.startPos = { row: 1, col: 1 };
    this.grid[1][1] = CELL_MAP.START;

    // 出口在最后一个奇数格子
    const endRow = this.rows % 2 === 0 ? this.rows - 3 : this.rows - 2;
    const endCol = this.cols % 2 === 0 ? this.cols - 3 : this.cols - 2;
    this.endPos = { row: endRow, col: endCol };
    this.grid[endRow][endCol] = CELL_MAP.END;
}
```

出口为什么不是 `rows-1, cols-1`？因为 DFS 从 (1,1) 出发，步进 2，能到达的最大奇数索引就是最后那行/列的最末奇数格子。

### 1.5 迷宫数据模型

```
this.grid 是一个二维数组，每个格子的取值：

0 = PATH  → 通路（玩家可通行）
1 = WALL  → 墙壁（阻挡）
2 = START → 起点
3 = END   → 终点

示例（3×3）：
  WALL  WALL  WALL       [1, 1, 1]
  START PATH WALL    →   [2, 0, 1]
  WALL  PATH END         [1, 0, 3]
```

### 1.6 难度配置

来自 `config.js`：

```javascript
export const DIFFICULTY = {
    easy:   { rows: 10, cols: 10, label: 'Easy (10×10)'   },
    medium: { rows: 20, cols: 20, label: 'Medium (20×20)' },
    hard:   { rows: 30, cols: 30, label: 'Hard (30×30)'   },

```

三个等级的格子数分别是 100、400、900，通路数大约为格子数的 **1/4**（因为只有奇数×奇数的格子是通路），即约 25、100、225 格通路，加上步进 2 的随机分支结构，可确保不同难度的路径长度有明显区分。

**对本项目的意义**：BCI 控制精度有限时（初学），可选择 easy 模式降低认知负荷；随着玩家对运动想象控制的熟练度提升，逐渐切换到 medium/hard，保持挑战性。

## 2. BFS 最短寻路算法

### 2.1 算法选择：为什么用 BFS？

| 特性 | 本项目的需求 | BFS |
|------|------------|-----|
| 最短路径 | 玩家"提示"功能要显示最近路线 | ✅ 保证最短 |
| 无权重 | 迷宫每条通路代价相同（一步 = 1） | ✅ 适合等权图 |
| 可解释性 | 逐层扩散的过程易于理解 | ✅ |
| 计算效率 | 30×30=900 格子，BFS ≤ 900 步 | ✅ 毫秒级 |

> 对比：Dijkstra 在无权图上等价于 BFS 但更复杂；A* 需要启发式函数，在无权的矩形迷宫中并不比 BFS 快。

### 2.2 算法流程

```
输入：迷宫网格、起点 (sr, sc)、终点 (er, ec)

① 创建 visited 二维布尔数组（记录已访问格子）
② 创建 parent 二维数组（记录每个格子是从哪个格子来的）
③ 将起点入队，标记为已访问

④ 循环（队列不为空时）：
   a. 取出队首元素
   b. 如果是终点 → 跳转到步骤⑤
   c. 遍历四个方向的相邻格子：
      - 如果是通路（PATH/START/END）且未访问
      - 标记为已访问
      - 记录 parent（从当前格子走过来的）
      - 入队

⑤ 从终点开始，沿着 parent 链反向追溯到起点，得到完整路径
```

### 2.3 代码解析

来自 `pathfinder.js`：

```javascript
findShortestPath(sr, sc, er, ec) {
    // 初始化访问标记和父节点记录
    const visited = Array.from(
        { length: rows }, () => new Array(cols).fill(false)
    );
    const parent = Array.from(
        { length: rows }, () => new Array(cols).fill(null)
    );

    const queue = [{ row: sr, col: sc }];
    visited[sr][sc] = true;

    const dirs = [[-1,0],[1,0],[0,-1],[0,1]];  // 上下左右

    while (queue.length > 0) {
        const { row, col } = queue.shift();  // 出队

        // 到达终点 → 重构路径
        if (row === er && col === ec) {
            return this._reconstructPath(parent, sr, sc, er, ec);
        }

        // 遍历四个邻居
        for (const [dr, dc] of dirs) {
            const nr = row + dr;
            const nc = col + dc;
            if (this.maze.isPassable(nr, nc) && !visited[nr][nc]) {
                visited[nr][nc] = true;
                parent[nr][nc] = { row, col };
                queue.push({ row: nr, col: nc });
            }
        }
    }
    return [];  // 理论上不会执行（DFS 生成的迷宫必然连通）
}
```

**路径重构**：

```javascript
_reconstructPath(parent, sr, sc, er, ec) {
    const path = [];
    let cur = { row: er, col: ec };

    while (cur !== null) {
        path.push(cur);
        if (cur.row === sr && cur.col === sc) break;
        cur = parent[cur.row]?.[col] ?? null;
    }

    return path.reverse();  // 从起点到终点的顺序
}
```

### 2.4 可视化效果

在游戏中，调用 `showHint()` 时，BFS 计算的路径以半透明高亮叠加显示在迷宫上，每个路径点画一个黄色小方块：

```javascript
// renderer.js
_drawHintPath() {
    for (const { row, col } of this.hintPath) {
        ctx.fillStyle = COLORS.hint;        // 半透明紫色背景
        ctx.fillRect(col * cs, row * cs, cs, cs);
        ctx.fillStyle = COLORS.hintPath;    // 黄色路径点
        ctx.fillRect(col * cs + cs * 0.35, row * cs + cs * 0.35, cs * 0.3, cs * 0.3);
    }
}
```

路径显示 3 秒后自动消失（`HINT_DURATION_MS = 3000`），既提供帮助又不降低探索趣味性。

### 3.2 玩家移动判定

```javascript
// game.js
_movePlayer(dir) {
    const moved = this.player.move(dir, this.maze, MOVE_COOLDOWN_MS);
    if (!moved) return;  // 撞墙 或 冷却中

    // 更新 HUD
    this.renderer.updateHUD(this.elapsedTime, this.player.steps);

```

## 4. 答辩 Q&A

### Q1：DFS 迷宫能否保证有解？

能。DFS 保证所有奇数格子都是连通的，入口 (1,1) 和出口（最后一个奇数格子）必然有一条路径连接。实际上 DFS 生成的是一棵**生成树**——每条通路都是树的一个节点，任意两个节点之间**有且仅有一条**路径。

### Q2：步进 2 会导致迷宫通路太少吗？

不会。对于 rows×cols 的网格，通路数 ≈ (rows/2) × (cols/2)。以中等难度 20×20 为例，通路数约 100 格，足够形成丰富的分支结构，玩家需要 100+ 步才能通关。

### Q3：BCI 控制时，BFS 路径提示是否必要？

非常必要。BCI 控制不像键盘那样可以"瞬间转向"，玩家在岔路口需要更长的决策时间。3 秒的路径提示可以帮助玩家减少迷路时的认知负荷，提升游玩体验。这也是"沉浸感"设计的一部分——不因脑控操作精度不足而让玩家感到挫败。

### Q4：30×30 难度的迷宫，DFS 和 BFS 计算需要多久？

两者都在**毫秒级**完成（<10ms）。DFS 生成时每个格子最多入栈/出栈各一次（30×30 = 900 步），BFS 同理。这远低于 60fps 游戏循环的 16.6ms 帧预算，对性能无影响。

### Q5：脑控迷宫和普通键盘迷宫在这些算法上有区别吗？

算法本身没有区别。区别在于**交互层**：
- 键盘玩家用方向键移动，每次按键移动一格，即时响应
- BCI 玩家发出"前进"想象指令，系统经过滑窗+投票后输出指令，延迟约 100-200ms
- `MOVE_COOLDOWN_MS = 120ms` 同时适用于两类玩家，但对 BCI 玩家起到了"去抖动"的作用
