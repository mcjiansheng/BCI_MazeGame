# MI 代码审查与本机验证记录

日期：2026-09-05。范围：LK-Mini 设备接入、记录、训练、实时分类、布局元数据与 Windows 启动入口。Unity 场景和 BCIC 深度学习模型不是本次完整审查范围。

## 已发现并修复的问题

| 优先级 | 问题及影响 | 修复与验证 |
| --- | --- | --- |
| P1 | 旧十六通道默认表重排 core-8，与小组实际线束不符，导致数据列被错误标注 | `source.py` 默认表由原八路加新增八路组成；文档同步；测试明确断言前八路与旧布局相同 |
| P1 | 把 Wi-Fi 接收时间当成 ADC 采样时间，会把网络批量到达误判为丢样；原采集/在线又未检查真实数据断点 | 真机原始诊断确认包序号连续而接收时间成批；BrainFlow 源现在检查循环包序号并建立样本时钟；采集及在线检查时间连续性；检查文件另存原始接收时间和整段吞吐 |
| P1 | 原在线质量门限只拒绝 bad，严重 50 Hz 污染即使占功率的大多数也可能以 warning 进入模型 | 在线 warning/bad 均返回 unknown，清空平滑历史；新增 16 路工频信号拒识测试 |
| P2 | 先前新增的 `24/gain` 补偿重复换算非 x24 数据，导致幅值偏大 | 核对 BrainFlow 5.22.2 的 `cyton_daisy_wifi.cpp` 后确认其已跟踪各通道增益；删除额外缩放，x6/x12/x24 测试确认保留库返回的微伏值。旧 x6 诊断幅值偏大四倍，不用于质量结论；真实电压标定未做 |
| P2 | 训练带通后的 `nan_to_num` 可掩盖输入 NaN/Inf，使损坏试次继续参与拟合 | 在进入滤波/CSP 前拒绝非有限 EEG；测试 NaN/Inf 两种情况 |
| P2 | 回放重新生成等间隔时间戳会掩盖原记录缺口 | 有原始样本时间戳时保留相对间隔，旧无时间戳文件才退回采样率生成；新增间断回放测试 |
| P2 | 视觉采集允许非实时数据高速生成、允许超过两个类别，而训练器为二分类 | 视觉采集禁止 `--no-realtime`；任务类别限制为恰好两个；仿真自动验收仍有独立入口 |
| P2 | 原虚拟环境继承全局 Anaconda 包，存在 OpenCV/NumPy 依赖冲突 | 建立 `.venv-mi` 独立 CPU 环境，`requirements-mi.txt` 固定主要版本，`pip check` 通过 |
| P2 | Windows 条件代码块可能丢失子进程失败退出码 | 启动器使用独立跳转分支传递退出码，回归测试确认无效参数返回非零 |
| P2 | 设备检查读数异常时直接退出，未保存已收到的诊断片段 | 检查入口保留断点前数据、写入中断标记和错误原因、返回失败码；初始化失败和中途断流两种场景均有测试 |

代码定位：`src/bci_maze/lk_mini/source.py`、`timing.py`、`recording.py`、`model.py`、`online.py`，以及 `scripts/lk_mini_check.py`、`collect_lk_mi.py`、`online_lk_mi.py`、`run_lk_mi.py`。

## 验证结果

- 原研究环境执行完整 pytest：69 项通过。
- `.venv-mi` 独立环境执行 LK-Mini 测试：51 项通过，包含硬件 API 模拟、x6/x12/x24 增益、后八路分类、时间间断、拒识、中断诊断保存、文件往返和启动器错误退出码。
- 新布局端到端软件验收通过；报告位于 `outputs/lk_mini_16_workflow/core8_preserved/workflow_report.json`。
- 实际打开仿真波形和中文采集窗口；练习文件包含 `2 × 16 × 1000` 的试次，电极顺序与小组图一致。波形渲染已检查。
- 真机短测成功：最初 5 秒收到 1260 点、16 路；另一次原始包诊断收到 744 点，743 个包增量均为 1。后续出现接收停顿和建连超时，所以不能宣布持续连接验收通过。
- 小组后续完成佩戴并重启。最新正式入口完成 60 秒采集，16 × 15012 点、整段 249.55 点/秒、包序号连续；最终 2 路 bad、4 路 warning。下一次初始化再次超时，连接仍不稳定。未采集带标签真人 MI 或训练真人模型。完整证据见 [断流诊断记录](LK_TRANSPORT_DIAGNOSIS_20260905.md)。

## 尚需实际实验验证的部分

1. 按断流诊断记录进行设备/接收器/电脑的对照排查，解决间歇性初始化超时和断流；正式采集前使用 `bci-mi.cmd check --backend brainflow --duration 60` 核查持续接收、整段吞吐及质量。
2. 按厂家线束定义确认参考、BIAS 与实际头皮位置。软件无法从波形确认物理接线标签正确。
3. 当前 trial 边界使用软件提示和接收缓冲区样本计数，没有硬件触发器/光电同步验证；网络缓冲和屏幕刷新造成的提示对齐误差仍需测量。适合初步四秒 MI 范式，不宣称毫秒级事件精度。
4. 二分类没有训练静息类别；高置信度不证明被试正在进行 MI。接入迷宫前应验证独立会话准确率和静息误触发率。
5. 已有同名输出可能被覆盖，正式实验使用独立 session 与模型文件名。模型文件只加载自己生成或可信来源的 joblib。
