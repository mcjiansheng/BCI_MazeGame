# MindMaze 本地控制台

本地控制台集中提供设备连接、实时脑电波形、逐通道信号质量、实验脚本启动、运行日志和 Unity 迷宫控制。界面在浏览器中运行，计算与设备通信由本机 Python 程序完成。

“05 / 子实验”区域提供真实握拳对照、运动想象信号分析和 CSP＋LDA 分组验证。新采集逐试次保存独立静息基线，报告集中显示时频变化、μ / β 功率、头皮分布、左右类别效应量和标签置乱对照。操作步骤与结果解释见[子实验说明](EXPERIMENTS.md)。

## 启动与操作流程

新电脑先按[安装与设备连接指南](FRESH_PC_SETUP.md)安装 `.venv-mi`、配套 USB 接收器驱动并配置设备网络。该指南列出 GitHub 文件与另行取得的厂商资料，以及第一次采集和文件检查步骤。

在仓库根目录双击 `bci-dashboard.cmd`，或运行：

```powershell
.\bci-mi.cmd ui
```

默认地址为 [http://127.0.0.1:8765](http://127.0.0.1:8765)。控制台使用本机已有的 `.venv-mi` 环境，启动界面无需额外安装依赖。界面初始为空闲状态，选择数据源并启动监测后才开始读取数据。

建议按以下顺序进行一轮实验：

1. 选择数据源及连接参数，启动监测，检查数据接收、16 路波形和逐通道质量。
2. 停止监测，等待采集资源释放，再启动 `collect` 采集任务。设置受试者、会话名称及采集预设，在独立的中文提示窗口中完成运动想象试次。
3. 使用保存的记录运行 `finetune`，对 SE-MHAF 公开预训练模型进行个人微调；需要 CSP＋LDA 对照模型时运行 `train`。
4. 在 Unity 中打开项目场景并进入 Play，检查控制台中的游戏状态，再运行 `online` 加载个人模型进行实时识别和迷宫控制。

控制台监测与脚本任务互斥，同一时间运行一个任务。切换前停止当前监测或任务，并等待状态完成更新。采集提示及在线概率图沿用项目的独立窗口，脚本输出同步显示在控制台日志区。SE-MHAF 微调及 `.pt` 模型的在线推理沿用项目中包含 PyTorch 的 `.venv` 环境。

记录从 `data/recordings/` 中选择，模型从 `outputs/subject_models/` 或 `outputs/pretrained/` 中选择。新采集记录和个人模型使用带独立后缀的文件名保存；在线日志位于 `outputs/online/`。每个任务显示对应的输出路径，完成后可用于下一阶段。

## 数据源与运行状态

“监测用途”与“设备佩戴状态”分别设置。选择“连接监测”后，页面显示采集器原始连接阶段、样本接收、连接尝试、中断、失败、成功重连和近期恢复事件；选择“信号质量检查”后查看逐通道质量。佩戴状态由操作者按实际情况选择“已佩戴”“未佩戴”或“待确认”，默认待确认。

两项选择分别保存在当前浏览器会话中，运行时切换展示保持采集连接。子实验采集启动时将操作者声明的佩戴状态写入记录；数据来源及真人运动想象验证状态沿用各自的记录字段。

BrainFlow 数据源可选择两套连接恢复配置。标准配置保持现有默认；快速配置用于连接恢复试测，实际效果按设备收数和恢复记录评价。监测以及从控制台启动的采集、在线识别任务使用所选配置。

| 参数 | 标准恢复 | 快速恢复 |
| --- | ---: | ---: |
| 无数据检测 | 3 秒 | 1.5 秒 |
| 旧进程停止宽限 | 4 秒 | 1.5 秒 |
| 首次重试间隔 | 0.5 秒 | 0.2 秒 |
| 最大重试间隔 | 3 秒 | 1 秒 |
| 设备 HTTP 请求超时 | 5 秒 | 2 秒 |
| 单次连接等待上限 | 12 秒 | 8 秒 |

超过停止宽限后，程序终止自己创建的采集工作进程，确认退出后再建立新会话。完整恢复耗时同时受设备响应、原生网络库和通道初始化影响，控制台记录实际恢复事件。

| 数据源 | 输入与用途 |
| --- | --- |
| BrainFlow | 通过 Wi-Fi 直连 LK-Mini-EEG16，读取真实设备数据。默认设备地址为 `192.168.4.1`，端口为 `12345`。 |
| LSL | 读取 OpenBCI GUI 发布的 EEG 数据流，使用对应的流名称和通道配置。 |
| NPZ 回放 | 读取已保存的项目记录，按记录中的采样率与通道信息显示信号。 |
| 合成信号 | 生成模拟脑电，用于熟悉操作及检查软件流程。界面显示其数据来源。 |

设备链路状态与信号质量分别显示。连接状态反映正在连接、收数、重连、停止或出错；采样点数、采样率、距离最新数据的时间和断流次数帮助定位数据传输问题。逐通道质量反映当前窗口内的脑电数值与频谱特征。

默认通道顺序为 `FC3、FC4、C3、Cz、C4、CP3、CPz、CP4、Fz、FC1、FCz、FC2、C5、C6、CP1、CP2`，依次对应 CH1–CH16。实际接线、帽位、数据源配置和模型输入使用同一顺序。SRB2 参考与 BIAS 偏置电极单独连接。

BrainFlow 采集沿用项目自动恢复机制：按所选配置的无数据阈值或检测到的包序号异常触发会话重建。进入恢复状态或切换数据段后，质量显示重新积累有效窗口。恢复事件、重新连接次数与当前状态用于观察设备到电脑的传输连续性。

## 信号质量与电极接触

控制台复用 `src/bci_maze/lk_mini/quality.py` 的信号质量计算。质量表显示逐路峰峰值、50 Hz 干扰占比和质量状态；展开“查看通道完整指标”并选择通道，可查看去中位数后的均方根幅度、平直比例及有效数值比例。幅度单位为微伏（µV）。

| 状态 | 当前计算条件 |
| --- | --- |
| 异常 | 存在非有限数值；相邻采样点近乎不变的比例超过 20%；峰峰值低于 1 µV 或高于 1000 µV。 |
| 需调整 | 通过上述异常检查后，50 Hz 干扰占比超过 35%，或峰峰值超过 500 µV。 |
| 良好 | 当前窗口通过上述检查。 |

50 Hz 干扰占比采用 48–52 Hz 频带功率除以 4–40 Hz 与 48–52 Hz 两部分功率之和。启动、断流或切换来源后，需要先积累信号再给出质量状态；连接恢复或窗口不足时显示“质量待评估”，通道质量计数在取得完整评估窗口后更新。在线识别遇到任一路“需调整”或“异常”时，返回 `unknown`，并清空先前的概率平滑历史。

电极接触变差、线缆松动、身体移动和环境电干扰均可能引起幅度或频谱异常。波形质量用于定位需要检查的通道；接触阻抗测量用于评估电极与头皮之间的电连接。当前控制台的接触信息来自波形质量，阻抗数值显示为尚未接入。

LK-Mini-EEG16 厂商通信协议第 4 页定义了阻抗测试命令 `z(CHANNEL,PCHAN,NCHAN)Z`，可在指定输入上启用 31.5 Hz 交流测试信号。项目已经实现命令字符串生成函数，阻抗扫描与换算仍待接入。厂商流帧包含 EEG、采样序号与辅助数据，现有 Python 读取路径使用 EEG 和传输信息。

阻抗功能的后续工作集中为：核对 LK 硬件的测试电流、输入接法与换算参数；实现采集前逐通道扫描；在结束、取消和异常退出时关闭测试信号并恢复通道设置；使用已知电阻验证测量值，再记录佩戴后各通道的阻抗与随时间变化情况。OpenBCI 官方说明要求逐通道进行此类测试，以控制注入信号对其他通道的影响。

协议与计算依据：

- [LK-Mini-EEG16 厂商通信协议](../vendor/LK-Mini-EEG16/LK-Mini-EEG16-通信协议-20260814.pdf)，第 4–5 页。
- [OpenBCI Cyton 阻抗命令](https://docs.openbci.com/Cyton/CytonSDK/)。
- [OpenBCI 信号与阻抗组件](https://docs.openbci.com/Software/OpenBCISoftware/GUIWidgets/)。
- [项目 SE-MHAF 采集、微调与在线流程](SE_MHAF_LIVE.md)。

## Unity 状态与控制

Unity 进入 Play 后，通过本机 UDP `127.0.0.1:7777` 提供游戏状态和控制接口。控制台读取游戏回执显示当前运行状态，并提供暂停、继续、左转、右转和掉头操作。在线识别运行期间，手动入口保留状态查询与暂停；其他手动操作在停止识别后使用。游戏未响应时，界面显示连接结果，便于检查 Play 状态和端口配置。

`online` 任务沿用项目的路口决策流程、信号质量检查、模型来源校验和指令回执处理。停止在线任务后，程序执行退出清理并释放采集连接。具体模型条件、路口映射与训练记录要求见 [SE-MHAF 十六通道流程](SE_MHAF_LIVE.md)。

## 软件验证

浏览器验证覆盖 1440×900、1024×768 和 390×844 三种视口，检查数据源切换、仿真监测、停止后重启、质量详情、任务日志、文件选择与页面布局。启动后由用户点击开始监测；关闭监测、数据过期及连接恢复时清除旧质量显示。

实际脚本验证使用合成数据与回放：采集提示窗口运行 15 秒后停止，保存并重载 1 个完整试次，形状为 1×16×1000；40 试次的合成记录通过控制台完成 CSP＋LDA 训练和 SE-MHAF 微调，生成的 CSP 模型在回放在线识别中输出分类结果，停止后退出进程。测试记录和模型分别位于 `data/recordings/DASHBOARD_QA`、`data/recordings/DashboardVerify` 与 `outputs/subject_models/DASHBOARD_QA`，来源元数据保留合成标识。

子实验的浏览器验证已覆盖三种仿真入口及已有记录分析，任务完成并显示对应报告。通用合成源的提示采集中途停止后，保存了 2 个完整试次，左右手各 1 次；任务数组为 2×16×1000，配对基线为 2×16×500，同时记录 1 个丢弃试次。子实验方法、文件内容和操作说明见[子实验说明](EXPERIMENTS.md)。

自动测试覆盖监测互斥、连接分段、数据过期、参数与路径校验、HTTP 同源约束、任务环境选择、启动器退出路径及停止时的文件保存。

真实设备已完成未佩戴条件下的连接测试：300 秒观察收到 16×38,832 点，出现 11 次自然断流，连续稳定性验收未通过。网页快速配置分别在电池与外接电源条件下观察到一次 HTTP 停流后的自动恢复，耗时为 12.656 秒和 5.344 秒；外接电源阶段随后再次自然停流。完整参数、原始记录和验证结果保存在仓库本地的 `outputs/connection_20261031/live_134326/TEST_REPORT.md`。佩戴后的信号质量、运动想象评价与 Unity 实际导航联测为后续任务。
