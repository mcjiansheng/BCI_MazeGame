# 3D 第一人称迷宫 Demo

## 设计目标

将任务从“持续解码四个绝对方向”改为“在有意义的路口选择方向”。系统负责沿格子中心自动前进和处理只有一个出口的弯道，玩家主要提供左右选择；可选主动掉头，死胡同默认自动恢复。定位是大创演示，使用现有 Unity 工程和内置渲染，不引入部署系统、复杂门控或额外物理依赖。

默认 15 × 15，格子间距 2.8 m、步速 2.6 m/s、转向时间 0.45 s、路口等待 4 s、死胡同等待 2 s。墙体、步道、灯带和橙色出口在运行时生成；平滑转身，无鼠标视角与摇晃，降低脑机任务中的视觉干扰。

## 导航规则

| 场景 | 自动行为 | 玩家选择 |
| --- | --- | --- |
| 直道 | 持续前进 | 可提前预约左右，或掉头 |
| 只有一个出口的弯道 | 自动转向并前进 | 无需额外分类 |
| 直行＋侧向分岔 | 等待 4 秒后默认直行 | 期间左右转向可立即生效 |
| 无直行出口的 T 字路口 | 停止并持续等待 | 左或右，掉头也可 |
| 死胡同 | 默认 2 秒后掉头 | 可立即主动掉头；可关闭自动恢复 |
| 终点 | 停止并显示结果 | 新地图 |

预约只保留一个，新指令替换旧指令；转向在对应出口可走的格子中心执行。用户不必卡准输入瞬间，也不会因为多帧分类造成无限积压。持续输出同一类别仍可能在后续路口产生新的预约，这是 Demo 的宽松控制策略；脑机发送方已有的命令冷却可继续使用。

双分类不能主动表达第三类“掉头”。本版用自动死胡同恢复和键鼠主动掉头支持演示；在具备四分类模型时，可使用 `configs/label_maps/bcic2a_relative.json` 将双脚映射到 uturn。后续可在发送端加入长保持/双次意图等掉头手势，无需改变迷宫渲染。

## 实现边界

状态机为 Moving、Turning、Junction、DeadEnd、Complete，暂停单独表示，避免影响已有的导航状态。移动由格子拓扑约束，无需 Rigidbody/CharacterController；几何体负责渲染，路径不会穿过墙体。UDP 指令统一入主线程处理，ACK 包含导航状态，可供实验日志或后续路口提示模块使用。

渲染、HUD 和导航拆成三个脚本，修改外观无需改 EEG；改变分类映射无需改场景。重新生成地图时释放旧材质、根对象和小地图纹理。旧绝对方向指令名保留为相对操作别名，但语义已变化，历史 EEG 联调记录需按版本区分。
